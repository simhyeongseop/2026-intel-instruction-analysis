# MOVDIR64B 오류 설명 정정

## 문제점

기존 기록에서 as가 거부한 MOVDIR64B 입력을 분석할 때 오류 원인을 **절반만** 올바르게 설명했습니다.

## 잘못된 해석

원래 코드:
```asm
movdir64b cx, zmmword ptr [eax]
```

기존 설명:
- ❌ **"64비트 레지스터로 바꾸면 된다"** (이는 SENDUIPI 규칙을 그대로 옮긴 것)

실제로 시도한 수정:
```asm
movdir64b rcx, zmmword ptr [rax]  ← 여전히 거부됨 ❌
```

## 올바른 분석

이 입력에는 **두 개의 별개 문제**가 있습니다:

### 1️⃣ **메모리 크기 지시자 문제 (주 원인)**
```
문제: zmmword ptr
이유: MOVDIR64B의 메모리 피연산자는 **고정 크기 512바이트 블록**
      AVX-512의 zmm 레지스터 크기(512비트 = 64바이트)와 다름
      m512 형식을 사용해야 하는데, 문법상 크기 지시자를 생략하거나
      as가 암묵 크기로 처리해야 함
      
수정: movdir64b rcx, [rax]  ← as가 수용
      또는 올바른 크기 표기 방식 적용
```

### 2️⃣ **레지스터 폭 문제 (부차)**
```
문제: cx (16비트 레지스터)
이유: 64비트 모드에서는 주소 폭 == 레지스터 폭이어야 함
      - ecx(32비트) + [eax] ✅ 가능 (32비트 주소)
      - rcx(64비트) + [rax] ✅ 가능 (64비트 주소)  
      - cx(16비트) + [eax] ❌ 불가능 (폭 불일치)

수정: movdir64b ecx, [eax]  또는  rcx, [rax]
```

## as vs Clang의 엄격도 차이

테스트 결과:
- **as:** `movdir64b rcx, zmmword ptr [rax]` → 거부 ❌  
  (크기 지시자가 주어진 명령어를 먼저 거부)
  
- **Clang:** 동일 입력을 **수용** ✅  
  (더 관대한 해석 — m512의 암묵 크기로 처리)

이는 **버그가 아니라 도구의 엄격도 차이**입니다.

## 발표 시 언급사항

> "MOVDIR64B 입력에서 우리 생성기가 두 가지 실수를 했습니다:
> 첫째는 크기 지시자인데, m512는 512**바이트** 블록이지 zmm 크기가 아닙니다.
> 둘째는 레지스터 폭 제약을 반영하지 못했습니다.
> as는 둘 다 거부하지만, Clang은 크기 지시자는 관대하게 처리합니다."
