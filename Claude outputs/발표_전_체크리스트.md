- [ ] 4~5회 요청(rip-relative, 최대값 imm, 여러 번 생성)을 구현하지 않은 이유 준비

### 교수님 질문 예상

**Q1. 진짜 버그는 1개(objdump)뿐인가?**  
A: 네, 우리가 확정할 수 있는 것은 LSS/LFS/LGS 표시 오류 1종류입니다. 다른 추정 버그들은 재검토 중이거나 도구 제약입니다.

**Q2. 왜 생성기 오류는 못 고쳤나?**  
A: (시간 부족 / 우선순위 결정 필요 / 다른 일정) — 교수님 판단 필요

**Q3. 이 도구를 어디 쓸 건가?**  
A: 아직 정해지지 않았습니다. (1) 어셈블러 퍼징의 시드 생성기, (2) 차등 테스트 오라클, (3) 버그 카탈로그 생성 중 어느 것이 목표인지 명확히 필요합니다.

**Q4. as/clang 바이트가 다른 48건은?**  
A: 같은 뜻을 다르게 인코딩한 것입니다. 예: `add ecx, ecx`는 `01 c9`도 `03 c9`도 가능합니다. 의도한 인코딩이 실제로 테스트되었는지 확인하려면 생성기 재설계가 필요합니다.

## 🎬 라이브 시연 준비 (선택)

**시연할 경우:**
```bash
# 1단계: 바이너리 생성
echo ".byte 0x48, 0x0f, 0xb2, 0x08" | as -o /tmp/test.o

# 2단계: 잘못된 표시
objdump -d /tmp/test.o -M intel

# 3단계: 재어셈블 불가능 시범
echo ".intel_syntax noprefix" > /tmp/reasm.s
echo "lss rcx,FWORD PTR [rax]" >> /tmp/reasm.s
as /tmp/reasm.s -o /tmp/reasm.o  # 실패 예상
```

**장점:** 증거가 직관적임  
**위험:** 네트워크 문제, 도구 미설치 등  
**대비:** 스크린샷 미리 준비
