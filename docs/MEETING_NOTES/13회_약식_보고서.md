# 13회 약식 보고서 — 왕복 세 비교 전체 실행과 LLVM 쪽 발견 3건

작성일: 2026-11-11 · 브랜치 `sdm-review-093`(커밋 전) · 발표 원고 [SLIDES_13.md](../presentation/SLIDES_13.md)
기준: SDM Vol.2 325383-093US, GNU Binutils 2.47, LLVM 23.1.3, 산출물 `out/round2_20261111/`

## 1. 한 일

1. 5단계를 발표에서 설명한 흐름(as0 → b0 → as1 → b1 → as2)대로 세 비교(as0–as2, b0–b1, as1–as2)로 나눴다.
2. 서버에서 전체 라운드를 실행했다: 106,601케이스, 왕복 210,215건.
3. '다름'·'미대조'를 원인별로 분류하고, 매뉴얼 원문 → 바이트 → CPU 관측 순서로 원인을 확인했다.
4. 분석에서 드러난 3단계 판정 오류를 고쳤다(13건 재판정).
5. LLVM 기존 이슈를 검색했다. 제출은 하지 않았다.

## 3. 새 발견 3건 (LLVM, 미보고)

| | 내용 | 예 | 판정 상태 |
|---|---|---|---|
| ① | clang Intel 문법이 `iret`, `push/pop fs·gs`를 16비트로 조립 | `push fs` → `66 0F A0`(GNU·clang AT&T는 `0F A0`) | 도구 간 해석 차이. `push/pop fs·gs`는 보고 후보, `iret`은 매뉴얼이 두 해석 허용 |
| ② | llvm-mc Intel 출력이 크기를 적지 않아 자기 왕복에서 바이트가 바뀜 | `66 9C` → `pushf` → `9C`, `0F A0` → `push fs` → `66 0F A0` | 보고 후보 |
| ③ | GPR 소스 변환 10행에서 `{rn-sae}`를 GPR 뒤에 쓰면 clang Intel이 거부 | `vcvtsi2sd xmm0, xmm1, rcx, {rn-sae}` | 버그로 확정하지 않음(매뉴얼이 위치를 정하지 않음, 조용한 오조립 0건) |

- 원인: ①·②는 LLVM 명령 정의에서 크기 글자가 AT&T 문자열에만 있고(`"push{w}\t{%fs|fs}"`), 크기를 고르는 별칭이 AT&T용만
  있기 때문이다. `pushf`는 Intel용 별칭이 있다(2017년 이슈 #31383에서 같은 종류의 문제가 고쳐짐). ③은 Intel 문자열이
  `$dst, $src1, $rc, $src2`로 고정돼 있다.
- 기존 이슈: 세 건 모두 같은 내용의 열린 이슈를 찾지 못했다. 검색어·선례·소스 근거는
  [llvm_existing_issue_search_2026-11-11.md](../issues/llvm_existing_issue_search_2026-11-11.md).
- 같은 성격의 `mov cx, es`(clang Intel `8C C1`, 66H 빠짐)는 CPU에서 동작이 다른 것을 확인했다(`8C C1`은 RCX 상위 비트까지 0으로 덮어쓰고, `66 8C C1`은 하위 16비트만 바꾼다).

## 4. IRET — 두 해석 허용과 위험

- 매뉴얼이 `IRET` 철자를 두 크기에 섞어 써도 된다고 적었다. 그래서 `iret`은 GNU `CF`(32비트), clang Intel `66 CF`(16비트)이고
  어느 쪽도 64비트가 아니다. 네 조합이 같은 바이트를 내는 철자는 `iretq`뿐이다.
- 우리 실험의 소스·AT&T 변환은 바꾸지 않는다(철자를 우리가 고르면 실험 규칙에 어긋난다).
- CPU 관측(사용자 모드, Xeon E5-2650 v4): 크기가 다르면 프레임을 2·4·8바이트 칸으로 읽어, 8바이트 칸 프레임에서 #GP가 나거나
  같은 40바이트가 다른 CS:IP로 복귀한다.
- 위험한 경우: 툴체인 이식, 프레임 칸 자리 이동(복귀 주소 비트가 CS·FLAGS 자리로), 역어셈블 → 재조립 도구, push/pop 스택 균형.
  커널 경로 실증은 없다. 상세 [SIZE_MNEMONIC_RISK_2026-11-11.md](../SIZE_MNEMONIC_RISK_2026-11-11.md).

## 5. 우리 쪽 수정

- 3단계: `MOV r, Sreg` 레지스터 목적지 폭, `PUSH/POP FS·GS` 크기 행, 별칭 검사에서 N.E.·Invalid 행 제외. MOV·POP·PUSH·LEAVE
  820케이스만 재판정해 13건이 바뀌었다(원본 `cases/check_results.before_rejudge_20261111.csv`).
- AT&T 변환: `{rn-sae}`가 GPR 앞에 오던 40건을 고쳤다(다음 라운드부터 적용, 이번 라운드 결과는 보존).
- 회귀 216개 통과(skip 22).
