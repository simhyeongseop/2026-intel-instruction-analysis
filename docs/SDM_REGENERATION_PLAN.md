## 사용자 결정 (2026-10-09)

- 원문이 최우선이다. 검토자(에이전트)의 해석은 근거로 쓰지 않는다.
- MOV만이 아니라 지금까지 생성한 모든 니모닉·인스트럭션(ISA 4,210행)을 재검토한다.
- 총론을 이제 처음 봤으므로 조합 생성기(m3_combine)를 새로 쓴다는 기준으로 진행한다.
- 결정 1(64비트 모드 주소): 각 명령 절의 표·Description 원문을 근거로 정한다.
- 결정 2(방향 쌍 레지스터-레지스터): 공통 소스로는 '도달 불가'로 표시하고, GNU 소스에만 `{load}`/`{store}`를 붙인다.
- 화면: 조회와 최종 검사 도구 모두 터미널.

## 새 생성기 원칙

1. 오퍼랜드 값마다 근거를 붙인다: 어느 원문(명령 절의 표 칸·각주·Op/En·Description 문장, 또는 총론 기호 정의 SYMxxx·총론 절)이 그 값을 허용하는지.
2. 근거의 우선순위: 명령 절(표, 각주, Op/En, Description) > 총론. 둘이 충돌하거나 원문이 모호하면 값을 만들지 않고 `미확인`으로 두며, 두 원문을 함께 기록한다.
3. 원문이 값을 정하지 않는 곳(예: 나열된 레지스터 중 무엇을 쓸지)에는 기계적인 고정 선택 규칙만 쓴다. 규칙 자체를 문서화하고, 선택이 원문 해석처럼 보이지 않게 한다.
4. 기존 m3_combine과 과거 결과는 그대로 두고, 새 결과는 별도 snapshot에 쓴다. 기존 ID와의 대응은 lineage로 남긴다.

## 오퍼랜드 표기의 근거 분포 (tokens.csv 기준)

- 총론 3.1.1.3 정의로 바로 설명: 155종, 행-오퍼랜드 7,646건.
- 총론 정의의 조합(예: `/` 대안): 30종, 121건.
- 총론 3.1.1.3에 정의가 없음: 83종, 1,999건. 명령 절이나 총론 다른 절이 필요하다.
  예: `zmm1`, `xmm3/m128/m32bcst`(정의는 zmm/m512/m32bcst만 있음), `k2`, `tmm1`, `m2byte`, `mem`, `r32a`, `k1+1`, `<XMM0-7>`.

## 재검토 방법 (사용자 확인 필요)

- 주 에이전트: 새 생성기가 각 값의 근거를 자동 추적한다. 근거가 없거나 충돌한 행을 기계적으로 나열한다.
- Sol(Opus 에이전트): 명령 절 원문이 필요한 행(정의 없는 표기, 각주가 있는 행, Description이 크기·제약을 정하는 행)을 원문과 대조한다.
- 대조 후 불일치·미확인과 대표 사례를 사용자 확인 목록으로 만든다. MOV 44개 검토는 새 생성기 결과로 다시 한다.
