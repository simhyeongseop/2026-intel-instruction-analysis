# 12회 발표 PPT 제작 지침

원고: [SLIDES_12.md](SLIDES_12.md)(슬라이드 문구와 대본). 이 문서는 **어떻게 만들지**만 적는다.
문구·수치는 원고에서 그대로 복사하고 새로 쓰지 않는다.
슬라이드 생성 AI에 넣을 때는 이 문서와 원고, 아래 첨부 파일을 함께 넣는다.

## 1. 공통 설정

| 항목 | 값 |
|---|---|
| 비율 | 16:9 (33.867 × 19.05 cm) |
| 배경 | 흰색 `#FFFFFF`, 장식·아이콘·그라데이션·그림자 없음 |
| 글꼴 | 본문 맑은 고딕, 코드·바이트·명령어 Consolas |
| 제목 | 40pt 굵게, 왼쪽 위 정렬, 모든 장 같은 위치 |
| 본문 | 28pt, 한 장 4줄 이하, 글머리 기호는 `•` 하나만 |
| 표 | 24pt(원고에 "표 24pt 허용"이라고 쓴 장만), 머리글 행만 굵게, 세로선 없음, 가로선 얇은 회색 `#BBBBBB` |
| 여백 | 좌우 1.5cm, 위 1.2cm |
| 쪽 번호 | 오른쪽 아래 14pt 회색, 제목 장 제외 |
| 발표자 노트 | 원고의 **대본**을 그대로 붙여 넣는다. 슬라이드에는 넣지 않는다 |

### 색 규칙(3색만)

| 색 | 코드 | 쓰는 곳 |
|---|---|---|
| 검정 | `#111111` | 제목·본문 기본 |
| 빨강 | `#D32F2F` | 불일치·거부·오류 판단(원고에 "(빨강)" 표시한 줄, 결과 표의 0이 아닌 "명령 다름"·"거부" 칸) |
| 파랑 | `#1565C0` | 일치·정상(원고에 "(파랑)" 표시한 줄) |

- 색은 글자에만 쓴다. 칸 배경 채우기, 강조 상자, 굵은 숫자 확대는 하지 않는다.
- 바이트·명령어(`ff 18`, `call [rax]`)는 문장 안에서도 Consolas로 쓴다.

## 2. 첨부 파일

| 파일 | 장 | 넣는 방법 |
|---|---|---|
| `captures/7_far_call.png` | 8 | 가로 폭의 85% 이상, 본문 위쪽. 잘라내거나 다시 칠하지 않는다 |
| `captures/8_lss_fword.png` | 9 | 같은 방식 |

캡처는 LLVM 23.1.3·Binutils 2.47 실제 실행 출력이다. 화면 글자를 손으로 고치지 않는다.
다시 만들 때는 같은 폴더의 `.txt`를 고친 뒤 `python render.py 7_far_call.txt 8_lss_fword.txt`.

## 3. 장별 배치

| 장 | 배치 | 주의 |
|---|---|---|
| 1 제목 | 가운데 정렬, 제목 48pt / 부제 28pt / 이름·날짜 20pt | |
| 2 과제 | 글머리 4줄. "AT&T로 역어셈블"만 굵게 | 교수님 지시 요약이므로 우리 해석을 덧붙이지 않는다 |
| 3 아키텍처 | 위 1/4: 기존 단계 한 줄(①~④ 회색 `#777777`, ⑤만 검정 굵게). 아래 3/4: 5단계 도형(아래 4절) | 그림이 주인공. 글머리는 맨 아래 한 줄 |
| 4 실험 | 표 위, 글머리 2줄 아래 | 케이스 수는 오른쪽 정렬 |
| 5 비교 조건 | 왼쪽 절반 글머리 3줄, 오른쪽 절반 판정 표 | 표의 "검토 대상" 두 칸만 빨강 |
| 6 전체 결과 | 표가 화면 대부분, 아래 한 줄 | 빨강 칸: GNU 명령 다름 8·8, GNU Intel 거부 9, LLVM 명령 다름 1·25. 0인 칸은 검정 |
| 7 명령 같음 | 표 위, 글머리 2줄 아래 | "(EVEX)"·"(VEX)"는 바이트 뒤 작은 글씨 20pt 허용 |
| 8 LLVM 먼 호출 | 캡처 위, 글머리 3줄 아래 | `ff 10`(가까운 호출) 줄 빨강, AT&T 줄 파랑 |
| 9 GNU LSS | 8장과 같은 틀 | "거부" 줄 빨강, AT&T 줄 파랑 |
| 10 원인 | 글머리 4줄, 줄마다 앞의 굵은 이름 + 설명 | 빨강 2줄 / 파랑 1줄 / 마지막 "미조사" 줄은 검정 |
| 11 AVX512PF | 글머리 3줄, "#233852 → #233869 → 머지"는 한 줄 화살표 | 머지 줄 파랑 |
| 12 한계 | 글머리 3줄 | |

8·9장은 같은 틀(캡처 위치·크기·글머리 위치)로 맞춰 두 오류를 나란히 비교해 보이게 한다.

## 4. 3장 아키텍처 도형

PowerPoint 기본 도형(사각형, 화살표 연결선)만 쓴다. 테두리 검정 1.5pt, 채우기 없음, 글자 20pt.

```
                 ┌→ [AT&T 텍스트] → [다시 조립 → Ba] → [다시 풀기] ─┐
[B0: 3단계 바이트] ┤                                                  ├→ [B0·Ba·Bi 비교]
                 └→ [Intel 텍스트] → [다시 조립 → Bi] → [다시 풀기] ─┘
```

- 상자 7개: B0, AT&T 텍스트, Intel 텍스트, 다시 조립 → Ba, 다시 조립 → Bi, 다시 풀기(2개), 비교 상자 1개.
- 위 줄(AT&T 경로)은 교수님 화이트보드 경로다. 위 줄 왼쪽에 작은 글씨 16pt 회색 "화이트보드 경로", 아래 줄에 "추가한 비교 경로"라고 적는다.
- 계열 표시: 그림 아래 한 줄 20pt "GNU: objdump → as / LLVM: llvm-mc → clang".
- 색은 쓰지 않는다(결과가 아니라 구조 그림이므로).

## 5. 하지 말 것

- 원고에 없는 수치·주장 추가 금지. 특히 "미조사 5건"을 오류라고 쓰지 않는다.
- "버그 확정" 표현 금지. 원고 표현 그대로 "오류로 판단", "검토 대상"을 쓴다.
- 결과 표를 그래프로 바꾸지 않는다(칸 값이 작아 막대가 보이지 않음).
- 캡처를 다시 타이핑해 텍스트 상자로 만들지 않는다.
- 슬라이드에 대본 문장을 넣지 않는다.
