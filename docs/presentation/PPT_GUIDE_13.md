# 13회 발표 PPT 제작 지침

원고: [SLIDES_13.md](SLIDES_13.md)(슬라이드 글과 대본). 이 문서는 **어떻게 만들지**만 적는다.
글·수치는 원고에서 그대로 옮긴다. 새로 쓰지 않는다.
슬라이드 생성 AI에 넣을 때는 이 문서와 원고, [PPT_GUIDE_12.md](PPT_GUIDE_12.md)를 함께 넣는다.

## 1. 흐름(이 순서를 바꾸지 않는다)

| 묶음 | 장 | 말하는 것 |
|---|---|---|
| 실험 설계 | 2, 3 | 세 비교(as0–as2, b0–b1, as1–as2) · 네 길(GNU/LLVM × AT&T/Intel) |
| 결과 | 4 | 일치 / 불일치 / 미대조 수 |
| 왜 | 5 | 미대조 |
| 왜 | 6 | as0–as2 불일치(적는 법 차이) |
| 왜 | 7~11 | 바이트까지 다른 것 다섯 가지, 한 장에 하나 |
| 왜 | 12 | `iret` |
| 정리 | 13 | 결과와 이유를 표 하나로 |

## 2. 글 쓰는 규칙

- 글은 적게. 한 장에 글머리 3줄까지. 넘치면 글자를 줄이지 말고 발표자 노트로 내린다.
- 쉬운 말만 쓴다. 원고에 없는 낱말(특히 어려운 한자말)을 넣지 않는다.
- 결과 낱말은 **일치 / 불일치 / 미대조** 세 개만 쓴다. "같음·다름"으로 바꾸지 않는다.
- 쓰지 않는 말: "버그 확정", "취약점 발견", "모든 CPU에서", "기존 이슈가 없다"("못 찾았다"로 쓴다).
- 발표자 노트에는 원고의 **대본**을 그대로 넣는다.

## 3. 공통 설정

12회와 같다. `PPT_GUIDE_12.md` 1절(16:9, 흰 배경, 맑은 고딕 / Consolas, 색 3개, 여백)을 따른다.
- 빨강: 원고에 "(빨강)"이라고 쓴 칸·줄 — 뜻이 달라지는 것
- 파랑: 원고에 "(파랑)"이라고 쓴 칸·줄 — 문제 아닌 것
- 붙이는 그림 파일은 없다. 바이트와 명령은 모두 Consolas.

## 4. 장별 배치

| 장 | 배치 | 주의 |
|---|---|---|
| 1 제목 | 가운데, 제목 48pt / 부제 28pt / 이름·날짜 20pt | 부제는 Consolas |
| 2 설계 ① | 위 절반: 흐름 그림(상자 5개와 화살표). 아래 절반: 비교 표 | 그림에서 비교하는 쌍을 선으로 잇는다(as0–as2, b0–b1, as1–as2). 다른 꾸밈 없음 |
| 3 설계 ② | 2×2 표가 가운데, 아래 글머리 2줄 | 표 칸 네 개가 4장 표의 줄 이름과 같아야 한다 |
| 4 결과 | 표가 화면 대부분(20pt), 아래 2줄 | 숫자 오른쪽 정렬. 빨강은 LLVM Intel 256·244만. 다른 칸은 검정 |
| 5~11 | "왜" 틀(5절) | 제목의 번호 ①~⑤를 빼지 않는다 |
| 12 `iret` | 글머리 3줄. 매뉴얼 영어 글은 그대로 | `iretq` 낱말만 파랑 |
| 13 정리 | 표 하나 + 아래 1줄 | 마지막 줄 "어디까지 보고할지 여쭙고 진행"만 굵게 |

## 5. "왜" 틀(5~11장)

일곱 장을 넘길 때 같은 자리에 같은 내용이 보이게 한다.

```
┌────────────────────────────────────────────┐
│ 제목 (40pt)                                 │
│ 얼마나   한 줄 (28pt, 수는 굵게)             │
├────────────────────────┬───────────────────┤
│ 예시 (왼쪽 55%)         │ 왜 (오른쪽 45%)    │
│ 표 24pt 또는 한 줄      │ 글머리 3줄까지 24pt│
└────────────────────────┴───────────────────┘
```

- 칸 이름 "얼마나", "예시", "왜"는 굵게, 원고 글자 그대로.
- 칸 테두리는 그리지 않는다. 위 그림은 자리만 보여 준다.
- 예시가 한 줄(7, 8장)이면 화살표(→)마다 줄을 바꿔 세로로 쌓는다.
- "왜" 칸에서만 24pt를 허용한다.
- LLVM 정의 글자 `"push{w}\t{%fs|fs}"`는 따옴표까지 그대로 Consolas.
